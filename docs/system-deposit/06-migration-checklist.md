# 迁移检查表

## 改动前检查

- [ ] 明确本次改动属于哪个阶段。
- [ ] 确认不会删除历史数据文件、Excel、JSON 和采集结果。
- [ ] 确认是否需要保留旧接口 path。
- [ ] 确认是否涉及数据库 schema。
- [ ] 确认是否涉及外部站点采集。
- [ ] 确认是否涉及本地 `.env` 或数据库凭据。

## 基础治理检查

- [x] 新增 `.env.example`，不包含真实密码。
- [x] 所有已提交脚本读取 `MYSQL_DSN` 或配置对象，不硬编码密码。
- [ ] README 中只保留示例凭据。
- [ ] 明确使用 `backend/.venv` 或重新统一虚拟环境。
- [x] `requirements.txt` 覆盖当前后端运行依赖。
- [x] `python-dotenv`、`python-multipart` 已加入运行依赖；`httpx` 暂未加入，需在补 API 自动化测试时确认。
- [ ] 后端启动命令可复制执行。
- [ ] 后端端口在 README、Vite proxy、OpenAPI 中一致。

## 数据库检查

- [ ] 主 schema 包含核心表。
- [ ] 保存时间段表和组合表纳入统一初始化。
- [ ] 目录表有种子数据导入方式。
- [ ] 价格表唯一键符合业务口径。
- [ ] 当前 `prices` 唯一键不含 `price_type`、来源、规格的问题已处理或明确保留。
- [x] 第一阶段图表、录入、手工批量录入已显式传递 `unit`；数据库仍需后续迁移标准化历史混合单位。
- [ ] 日期字段含义明确。

## API 检查

- [x] `GET /api/prices` 查询 API 不触发外部采集或 mock，只读取数据库。
- [x] `GET /api/prices` 已校验 `price_type` 和 `unit` 查询参数。
- [ ] 批量导入返回批次 ID 或完整错误明细。
- [ ] POST 请求复杂参数放 body，不放 query。
- [ ] 返回结构统一。
- [ ] OpenAPI 或接口文档同步更新。

## 前端检查

- [x] 图表页不再读取 `/config.yaml`，改为读取后端目录 API。
- [ ] 前端不再维护鱼种/市场静态配置。

- [ ] 目录数据统一进入 Pinia store。
- [x] 图表页已收敛为单市场、单鱼种查询，和当前后端接口能力一致。
- [ ] 图表页请求和图表渲染拆开。
- [ ] 保存时间段不通过全局 window event 做长期方案。

- [ ] 移动端和常见桌面尺寸不出现明显遮挡。
