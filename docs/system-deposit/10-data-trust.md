# 数据可信度策略

## 背景

用户补充业务判断：除“民众渔业”的数据外，其他历史数据可能都有问题。

因此，后续重构不能把当前 `prices` 表中的全部数据都当作可信历史价格。系统必须支持数据可信度分层、隔离和逐步校验。

## 当前数据可信度初判

| 数据范围 | 当前规模 | 初始判断 | 风险 |
| --- | ---: | --- | --- |
| 泥鳅 / 民众渔业 `fish_id=2, market_id=104` | 184 | 相对可信候选 | 仍有 171 条缺少 `source_url`，单位为 `kg`，需确认是否实际代表元/斤 |
| 鲈鱼 / 江苏省综合市场 `fish_id=1, market_id=103` | 215 | 高风险 | 全部缺少 `source_url`，同日多价格点跨度大，market 103 在前端配置中曾被写成浙江湖州 |
| 黄颡鱼相关数据 `fish_id=5` | 118 | 高风险 / 待确认 | 单位为 `斤`，来源和规格口径需要复核，目录 code 与 YAML 不一致 |
| 草鱼、鲢鱼 | 0 | 无数据 | 目录存在但主表无价格数据 |
| `prices_back0319` | 903 | 备份 / 待确认 | 不确认来源前不能回灌或覆盖主表 |

## 建议质量状态

目标价格模型建议增加 `quality_status`：

| 状态 | 含义 | 默认展示 |
| --- | --- | --- |
| `trusted` | 已确认口径和来源，可用于正式图表 | 是 |
| `trusted_candidate` | 来源相对可信，但仍有单位或来源缺口 | 可配置 |
| `unverified` | 未校验，不应默认用于正式分析 | 否 |
| `suspect` | 已知存在明显风险 | 否 |
| `rejected` | 确认无效，仅保留审计 | 否 |

第一阶段可以先用简单规则：

- 民众渔业数据标记为 `trusted_candidate`。
- 非民众渔业主表数据标记为 `unverified` 或 `suspect`。
- 备份表数据不进入正式查询。

## 查询策略

默认查询：

```text
只返回 trusted 或 trusted_candidate 数据
```

调试/校验查询：

```text
允许通过参数 include_unverified=true 显示待校验数据
```

图表展示：

- 默认图表不混入 `suspect` 数据。
- 如果显示待校验数据，必须在图例、tooltip 或页面状态中明确提示。

## 迁移策略

建议迁移步骤：

1. 新建目标价格表或给现有表增加质量字段。
2. 按来源和鱼种市场组合批量打初始质量标记。
3. 先迁移民众渔业数据作为验证基线。
4. 非民众渔业数据保留，但不进入默认查询。
5. 为高风险数据建立校验清单。

## 校验清单

非民众渔业数据进入可信曲线前，至少确认：

- 来源 URL 或原始文件是否存在。
- 日期是价格日期、文章日期还是入库日期。
- 单位是元/斤还是元/kg。
- 同日多价格点是否对应规格、地区或不同来源。
- 市场 id 和名称是否与当前目录一致。
- 是否存在明显异常价格。

## 对当前重构的要求

1. 不要用全量 `prices` 数据做默认图表回归。
2. 不要把 `prices_back0319` 自动并回主表。
3. 不要在没有质量状态的情况下重建查询 API。
4. 先以民众渔业数据跑通“可信数据闭环”。
5. 后续再逐个来源修复鲈鱼、黄颡鱼等数据。
